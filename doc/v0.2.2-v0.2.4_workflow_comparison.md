# v0.2.2 And v0.2.4 Workflow Comparison

Date: 2026-10-07

This is a same-corpus, offline deterministic comparison of the workflow
runner. Both tags use the same fake semantic provider, in-memory backend, and
checked-in title-plus-long-table corpus. It measures workflow behavior and
persisted graph shape; it is not a live-provider quality benchmark.

| Version | Status | Elapsed | Nodes | Max depth | Strategy history | Timeouts | Final coverage |
| --- | --- | ---: | ---: | ---: | --- | ---: | ---: |
| v0.2.2 | succeeded | 21,867 ms | 2 | 1 | excerpt_first | 0 | 1.0 |
| v0.2.4 | succeeded | 23,893 ms | 2 | 1 | excerpt_first | 0 | 1.0 |

The elapsed difference is approximately 2,026 ms in this single run and is
not treated as a performance regression without repeated measurements. The
structural result is equivalent for this deterministic legacy-compatible
workflow: both versions persisted two nodes, reached depth one, recorded the
same strategy, and retained complete source coverage.

## Reproduction

Run `scripts/compare_workflow_versions.py` from each tagged checkout with the
same `--source` fixture and compare the JSON records. The script creates no
provider calls and does not persist credentials or machine-specific paths.
