## Status And Evidence Rules

- `NOT STARTED`: not yet investigated.
- `REPRODUCED`: the baseline defect has been reproduced, but not fixed.
- `IN PROGRESS`: implementation or test work is underway.
- `VERIFIED`: implementation and required tests pass.
- `NOT VERIFIED`: unavailable provider, platform, or artifact prevents proof.
- `DEFERRED`: explicitly deferred with a recorded reason.
- Every `VERIFIED` item must include a commit, test name, and command or artifact.
- Every provider or strategy claim must name the actual mode or strategy.
- A final release cannot be declared while a required item is `NOT VERIFIED`.

## Update Protocol

1. Reproduce before modifying the relevant implementation.
2. Update the affected item to `REPRODUCED` with exact evidence.
3. Implement the smallest scoped fix and add the regression test.
4. Run the applicable mode and strategy matrix.
5. Update the item to `VERIFIED` only after the required evidence exists.
6. Record unresolved limitations as `NOT VERIFIED` or `DEFERRED`, never as passed.
7. Update this checklist in the same commit as the corresponding implementation or test change.

## Final Report Required From This Checklist

The final report must include root causes, edited functions, old and new
behavior, mode and strategy applicability, red/green evidence, terminal and
active frontier coverage, provider timing and timeout evidence, distribution
verification, and remaining limitations. Any item without direct evidence must
remain visibly unresolved.
